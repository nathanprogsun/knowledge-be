# Agent Note: Knowledge-base shares and org lists

Status: implemented
Date: 2026-09-05
Scope: wire KB share mutations and org-scoped KB share lists on existing contracts
Related files: src/core/sharing/kb_share_service.py, src/web/api/knowledge_bases/shares_router.py, src/web/api/organizations/shared_router.py, src/core/organizations/service/shared_resource_service.py, tests/web/test_kb_shares.py

## Context

The SPA share dialog already posted to `/knowledge-bases/{id}/shares` and listed org-scoped KB shares. Those HTTP routes were missing. Reads and `can_access_knowledge_base` already ran on `KBShareService`. Create, update, and revoke still raised `NotImplementedError`.

## Decision

Stored grant is `viewer` | `editor` | `admin` (`SHARE_PERMISSIONS`). The SPA radio sends `viewer` | `editor`. Anything outside the set is rejected. KB shares do not force viewer.

Receiver cap stays in `SharedResourceService` as `min(share.permission, org role, caller tenant role)`. Create stores the grant. List and read fill `my_role_in_org` / `my_permission` from a membership already in hand.

Who may mutate `POST` / `PUT` / `DELETE /knowledge-bases/{id}/shares`: KB `creator_id` or tenant Admin+. The original `shared_by_user_id` may manage an existing row. A receiving-org admin does not pass. HTTP floor is `RoleContributorDep` for mutations and `RoleViewerDep` for lists. A contributor who is not the creator and not a tenant admin is still 403 at the service.

Source scope: caller `tenant_id` must own the KB. Another tenant's KB id is 404.

Dest org: the source tenant must be a member of the target organization (`kb_share.tenant_not_in_org`). The caller does not need an org editor role to share a KB they own.

Duplicate live `(kb, org)` upgrades the existing grant's permission.

`GET /organizations/{id}/shared-knowledge-bases` lists direct KB shares only, including `is_mine`. `source_from_agent` stays absent. `GET /shared-knowledge-bases` is unchanged.

Service output is `KnowledgeBaseShareInfo.map_from_db`. Web never sees `src.db.models.kb_share.KnowledgeBaseShare`.

## Alternatives considered

- **Force viewer on KB grants** — rejected: agent shares do that because they are read-only. The SPA share radio sends `viewer` | `editor` and the stored grant is the product.
- **Let a dest-org-admin mutate** — rejected: the SPA `canShareKB` gate is creator or tenant Admin+. A receiving-org admin must not pass.
- **Pull agent-carried KBs into the org KB list** — rejected: `source_from_agent` is a later program. This list is direct KB shares only.
- **A fourth stored role** — rejected: `SHARE_PERMISSIONS` is already `viewer` | `editor` | `admin`.

## Consequences

The share dialog can create, list, update, and revoke KB grants. Org settings can list KB shares and org-scoped shared KBs. Agent-share org twins and agent-carried KBs stay unwired. Display names (`knowledge_base_name`, `shared_by_username`) stay empty unless a join is already in hand.
